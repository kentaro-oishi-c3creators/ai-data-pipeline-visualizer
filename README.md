# AI / データ変換パイプライン可視化

[公開デモを開く](https://kentaro-oishi-c3creators.github.io/ai-data-pipeline-visualizer/) · [GitHubのソースを見る](https://github.com/kentaro-oishi-c3creators/ai-data-pipeline-visualizer)

Source SQL → Semantic理解 → 処理単位への分解 → Qlik / 変換ステップ生成 → 統合 → 検証 / レビューを、左から右へ進むアニメーションとして探索するローカル試作品です。工程をクリックすると、入力、AI判断、決定論的処理、検証、Human review、provenance を確認できます。

## 起動

Node.js 20 以上を用意し、このフォルダーで次を実行します。

```powershell
npm install
npm run dev
```

表示された `http://127.0.0.1:5173/` をブラウザで開きます。ビルド確認は `npm run build` です。

## GitHub Pages で公開する場合

公開リポジトリの Pages Source は **GitHub Actions** です。`main` への push で `.github/workflows/deploy-pages.yml` が依存導入・型検査・ビルド・公開を実行します。Vite の `base` は Actions 上のリポジトリ名から自動設定し、ローカル起動は `/` のまま動きます。

`sources/` と `AGENTS.md` はこのローカル作業環境の参照資料で、公開対象から除外します。実案件の情報を追加する際は公開リポジトリと公開ページの両方に載ることを確認してください。

## 操作

- 六つの工程カードをクリックして詳細を表示します。
- 再生ボタンで工程が順番に進みます。停止、最初から、速度変更ができます。
- 「標準ケース」「要確認ケース」を切り替えられます。要確認ケースは二つの意味候補を自動選択せず、人の判断へ渡す説明です。
- 横幅の狭い画面では工程列を横スクロールできます。
- 「選んで、流れを変えてみる」では `sales_amt`、`net_amt`、判断保留を選べます。粒が右へ流れ、Qlik の変換案と検証結果が変わります。「出所をたどる」を押すと、選んだ元 SQL の列が光ります。保留時は二つの候補の出所を表示します。

## 判断分岐ミニ実験

この固定シナリオでは「売上金額＝値引き後」、期待値 1,800 と仮定しています。`sales_amt`（値引き前 2,000）を選ぶと差分 +200、`net_amt`（値引き後 1,800）なら一致、判断保留なら変換案の確定と検証を止めて Human review に渡します。これは操作の意味を見せるためのサンプルで、実案件の正解判定ではありません。

## 位置づけ

表示している SQL、候補、検証件数はすべて架空の説明用データです。実際の SQL 解析、AI 呼び出し、Qlik コード生成や検証は行いません。画面上の `provenance` は、どの根拠を保持すべきかを示します。

## 拡張案

1. 実案件の定義書・SQL・変換ログを読み取り、各ブロックと元行を対応づける。
2. AI の候補に実データ由来の理由、信頼度、複数候補を表示し、承認・差し戻しを記録する。
3. 実行結果 Excel、サマリー、ログを照合して検証状態を表示する。
4. 発表用の全画面表示と工程ごとの書き出しを追加する。

構成と実装境界は [docs/architecture.md](docs/architecture.md)、今回の完了条件は [docs/plan.md](docs/plan.md) に記録しています。
